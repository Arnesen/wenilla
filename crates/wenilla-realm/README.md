# wenilla-realm

The realm service: one process that serves the browser client behind a login, hands each
player their (hidden) game credentials, and gives the admin a panel to run the game server.
It wraps `wenilla-host`'s routers (`/data/*`, `/ws/{port}`, the wasm files) in a session
check, so nothing the game needs is reachable without signing in — the stock client cannot
connect at all, and no game or console port has to be exposed.

Packaged for a single VM with Docker Compose in **github.com/Arnesen/wenilla-realm** (that
repo is the place to start: `realmctl up`, then `/setup`). This crate is what runs inside the
`realm` container.

## What it does

- **Login blocker.** Username + password (argon2id) for admins and players; players are
  created by an admin in the panel and must change their password at first sign-in. Sessions
  are a random cookie token hashed at rest, `Secure; HttpOnly; SameSite=Lax`, rotating.
- **Play page** (`/`). Fetches `{user, pass, host}` from `GET /api/play` over the session and
  boots the wasm client with `window.__wenilla_env` — the game password is generated by the
  service, kept encrypted (ChaCha20-Poly1305 under `/state/master.key`) and never shown.
- **Admin panel** (`/admin`): server status and who is online; announce/notify; restart with a
  countdown (mangosd exits 2, the container restart policy brings it back); users — create,
  ban/unban, kick, reset web password, rotate game password, role, disable, delete (with
  characters); settings — XP/loot/money rates, player limit, save interval, max level, MOTD,
  random-bot count, auction-house bot, applied live through `reload config` where the core
  allows it; an audit log of everything.
- **Setup wizard** (`/setup`), gated by a one-time token printed at first start: admin account,
  realm name, presets. It also creates its own console account (`WRSOAP`) and re-passwords the
  seeded `ADMINISTRATOR`/`GAMEMASTER`/`MODERATOR`/`PLAYER` accounts.

## Configuration (environment)

| variable | default | meaning |
|---|---|---|
| `REALM_BIND` | `0.0.0.0:8090` | listen address (Caddy proxies to it) |
| `REALM_PUBLIC_URL` | `https://localhost` | what players open; also the only WebSocket `Origin` accepted |
| `REALM_STATE_DIR` | `/state` | `realm.sqlite`, `master.key`, `setup-token` |
| `REALM_WWW` | `/app/www` | the wasm dist (`wenilla.js`, `wenilla_bg.wasm`, `wasi_stubs.js`) |
| `CLIENT_DATA` | `/client/Data` | the operator's client `Data/` (read-only) |
| `CONFIG_DIR` | `/config` | `mangosd.conf`, `aiplayerbot.conf`, `ahbot.conf` — edited in place |
| `MARIADB_URL` | `mysql://realmweb:…@mariadb:3306/classicrealmd` | read-only game DB user (+ `UPDATE` on `realmlist`) |
| `SOAP_URL` | `http://mangosd:7878/` | mangosd's SOAP console |
| `SOAP_BOOTSTRAP_USER/PASS` | `ADMINISTRATOR`/`ADMINISTRATOR` | console login until the wizard has made `WRSOAP` |
| `REALMD_HOST`, `MANGOSD_HOST` | `realmd`, `mangosd` | where `/ws/3724` and `/ws/8085` are relayed |
| `WENILLA_DEV_QUERY_CREDS` | `0` | `1` lets `?user=&pass=` links log in (development only) |
| `REALM_COOKIE_INSECURE` | `0` | `1` drops the cookie's `Secure` flag (plain-http development only) |

`wenilla-realm reset-admin` forgets the admin's password and prints a fresh setup token; the
wizard then only sets a new admin password.

## Developing

```bash
cargo test -p wenilla-realm          # unit tests + an end-to-end pass through the router with a mock console
cargo run --release -p wenilla-realm # needs a running realmd/mangosd/MariaDB — see the env table
```

The integration test (`tests/app.rs`) drives the wizard, creates a player, signs in as them,
fetches `/api/play`, and checks that every game route answers 401 without a session and that
CSRF / cross-site posts are refused.
